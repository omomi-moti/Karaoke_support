# 0066. 検索タブは検索欄の下の標準の切り替えで、曲名と歌手名のどちらで探すかを選ぶ

- 2026-11-20 提案 ／ 2026-11-20 承認
- 背景：#105 で記録シートの「もしかして」は曲名からも歌手名からも引けるようになったが、検索タブは曲名でしか探せない。「米津」と打っても何も出ず、記録シートとの食い違いに気づきやすい（#179）。決めるのは、切り替えの置き場所、初期値と覚えておくか、打つ前に出す「最近歌った曲」を切り替えで変えるかの 3 つ

## 比較した案

1. 切り替えの置き場所
- A. 検索欄の下の標準の切り替え（SwiftUI の `searchScopes`）
- B. 画面の上に、履歴の気分の絞り込みと同じ見た目のチップを自前で並べる

2. 初期値と覚えておくか
- A. 毎回「曲名」から始め、覚えない
- B. 前に選んだ方を端末に覚える（`@AppStorage`）

3. 打つ前に出す「最近歌った曲」
- A. 切り替えても変えない（どちらでも最近歌った曲を 5 曲）
- B. 歌手名では、最近歌った歌手の一覧を出し、押すとその歌手で探す

## トレードオフ

1. 置き場所
- A は iOS の標準の見た目と動きで、コードも少ない。検索欄を開いている間だけ出る
- B はアプリの見た目にそろうが、選んだ状態や読み上げを自前で作ることになり、コードが増える

2. 初期値
- A は開いたときにどちらで探すかがいつも同じで迷わない。保存する状態も増えない。歌手名でよく探す人は毎回切り替える手間がある
- B は歌手名でよく探す人には便利だが、開いたときにどちらになっているかが分かりにくい

3. 最近歌った曲
- A は今の画面と同じで、行の形と＋の動きも変わらない
- B は歌手から探す人には近道になるが、歌手の行という新しい形と、押したときの動きを作ることになる

## 決めたこと

1. A。`.searchScopes(_:activation: .onSearchPresentation)` で、検索欄を開いた時点から「曲名｜歌手名」を出す。打つ前から選べるようにするため。検索欄の文も「曲名で探す」「歌手名で探す」に合わせて変える
2. A。`SearchViewModel.target` の初期値は曲名で、覚えない
3. A。最近歌った曲は切り替えで変えない
- 歌手名で探すときは `searchLocalByArtist` を使い、その歌手の歌ったことがある曲を出す。歌手名のない曲は出ない
- 行の中身と＋の動きは、曲名で探すときと同じ（`SearchResultDisplayItem`・`SearchResultRowView` をそのまま使う）
- 切り替えたら、今打っている文字で探し直す。打ち終わりを待つ時間と、古い結果で上書きしない仕組みは、曲名で探すときと同じものを使う

## 選んだ理由

- 1 は A。標準の部品なら、見た目・選んだ状態・読み上げを iOS がそろえてくれ、作るものが少ない。検索欄と同じ場所にあるので、何を切り替えるのかも分かりやすい
- 2 は A。曲名で探すことがいちばん多く、毎回同じところから始まるほうが迷わない。覚えると、保存する状態が増えるうえ、開いたときにどちらか分かりにくくなる
- 3 は A。今回の目的は、記録シートと同じく歌手名からも引けるようにすることで、打つ前の画面まで作り直す理由はない。今と同じ画面なら、行の形と動きを増やさずに済む

## 見直す条件

- 歌手名で探す人が多く、毎回切り替える手間が気になるという声が出たとき（2 の B）
- 曲名と歌手名を切り替えずに、両方から一度に探したくなったとき
- 表記ゆれ（#94〜#96）を直して、検索の当て方を変えたとき
