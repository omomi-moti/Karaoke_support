# 0050. DB は Postgres にし、Neon の無料枠に置く

- 2026-11-04 ／ 承認
- 背景：ADR 0048 で DB を Neon の Postgres にしたが、サービスを丸ごとの組で比べただけで、DB の種類と DB のサービスは比べていなかった。Issue 1（#146）で料金と地域を確かめると、Neon に東京がない、無料だと IP で絞れない、と分かった。0048 の判断は変えず、抜けていた比較を足す

## 判断を動かす要件

- データは端末が正で、サーバーは本人が頼んだときだけの控え（憲法 II、NFR-1）。サーバーが止まっても記録は消えず、アプリも動く。だから止まってもよい（NFR-10）
- 主な用途はバックアップ。MVP は記録を `jsonb` の塊で 1 人 1 行に置き換える（ADR 0049）
- 優先する順は、プライバシー → 費用（月 0 円）→ 安全 → 性能（数秒でよい、NFR-8）
- 使うのは自分と外部テスター数人。Go と SQL を学ぶことが目的の 1 つ（ADR 0048）

## 比較した案

1. DB の種類
- A. リレーショナル（Postgres）
- B. リレーショナル（MySQL）
- C. ドキュメント（Firestore）

2. DB のサービス
- A. Neon
- B. Supabase
- C. Cloud SQL
- D. Aiven

## トレードオフ

- 1-A は一意の制約・外部キー・トランザクションを DB に守らせられ、テーブルの変更もトランザクションに入るので、マイグレーションが途中で失敗しても丸ごと戻る。`jsonb` と `uuid` が使え、無料で置ける場所も多い。ただ MVP はバックアップを `jsonb` の塊で持つので、リレーショナルの良さを使うのは `users`・`auth_tokens` と置き換えだけ。本当に効くのは 2 台の同期（C2）から
- 1-B も作れるが、テーブルの変更は 1 文ごとに確定し、マイグレーションが途中で失敗すると半端な形が残る。無料で置ける場所が少ない
- 1-C は 0 円で東京に置け、Cloud Run のサービスアカウントの権限だけでつながる（パスワードが要らない）。ただ SQL を学べず、C2 の設計に合わない。1 文書 1MiB の上限があり、全件を 1 つに入れると記録が数千件で届く見込み
- 2-A は無料でカード不要、上限を超えても止まるだけで請求は来ない。5 分使わないと止まり、次のリクエストで自動で起きる。ブランチで staging と本番を分けられる。東京がなく（アジアはシンガポールとシドニー）、インターネットに出ていて、無料では IP で絞れないので、守りはパスワードと TLS だけ
- 2-B は東京に置け、止まらないので待ちがない。1 週間使わないと止まり、手で戻すまで動かない。認証などの機能を使わないのに抱える
- 2-C は公開しない接続と IAM でつなげ、安全は最も強い。無料枠がなく、常に課金される（月 8〜10 ドル前後。第三者の見積もり）
- 2-D は無料の Postgres だが、地域と接続数（20）の制約が強い

料金・無料枠・地域は 2026-11-03〜04 に確かめた（Neon の料金のページ、Neon と Supabase の地域の文書。Cloud SQL と Supabase の一部は第三者の資料）。ADR 0048 で「確かめていない」とした前提のうち、月 0 円で使えることは崩れていない。

## 選んだ理由

- 1 は A。バックアップが主なので、正直リレーショナルで普通に持てれば足りる。そのうえで、制約を DB に守らせたいこと、C2 で表とトランザクションが要ること、SQL を学ぶこと。MySQL より Postgres にしたのは、手で流すマイグレーションが失敗しても丸ごと戻るから。MVP だけならドキュメント型でも足りた
- 2 は A。普通の Postgres ならどれでも足りるので、0 円で請求が来ず、使わない日があっても自動で起きるものにした。標準の Postgres だけを使い、つなぎ先を `DATABASE_URL` で渡すので、合わなければ URL を替えるだけで移れる
- Neon はシンガポールに置く。Cloud Run は日本（東京）のまま。DB と 1 往復するたびに 70ms ほどかかるが、1 回のリクエストで数往復なので、NFR-8 の数秒に収まる。staging にデプロイしたら `/health` の応答時間を測って確かめる

## 見直す条件

- 使う人が増え、止まることや起きるまでの待ちで困ったとき（2 を B か C にする）
- Neon に東京ができたとき、または DB との往復の遅さで困ったとき（Neon を東京に移すか、2 を B にする）
- 2 台の同期（C2）を始めるとき（記録を表に分ける）
