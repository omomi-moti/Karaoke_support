# 0004. 非同期の古い結果は世代番号で捨てる

- 2026-07-28 ／ 承認
- 背景：履歴でフィルターの変更や削除が読み込みの完了と重なると、古い読み込み結果が新しい一覧を上書きする

## 比較した案
- A. 新しい読み込みを始めるときに古い `Task` を `cancel()` するだけにする
- B. 読み込みのたびに世代番号（`loadGeneration`）を進め、完了時に自分の世代が最新のときだけ結果を反映する

## トレードオフ
- A はコードが少ないが、キャンセルは非同期に伝わるので、キャンセルが届く前に完了した古い読み込みが一覧を書き換えてしまう
- B は確実に防げる。コストは `Int` の加算と比較だけだが、反映する箇所すべてで世代を確認する必要がある

## 選んだ理由
- B。A では競合を完全に防げない。`loadInitial`・`loadNextPageIfNeeded`・`deleteSession` で同じ仕組みを使える
- 読み込みが 1 本しかなく、持ち主が `.task` で決まっている画面（曲詳細）は、世代番号を使わず `Task.checkCancellation()` で古い結果を捨てる（I-019）

## 見直す条件
- 読み込みが 1 本の Task に集約でき、キャンセルだけで古い結果を確実に捨てられる構造になったとき
