# 0069. 押せる行には、押すと何が起きるかの印を出す（画面へ進む行は ›、記録シートが開く行は ＋）

- 2026-11-21 提案 ／ 2026-11-21 承認
- 背景：履歴の行は押すと曲詳細へ進むが、[0018](0018-history-row-navigation-with-button.md) でカードの外に出る › を消したので、押せるかどうかが分かりにくかった（#191）。選曲画面と保存直後のシートの候補カードも、押すと記録シートが開くのに、印がなかった。検索の行は [0052](0052-search-tab-tells-by-ui.md) で右端に ＋ を出している

## 比較した案

1. 履歴の行
- A. Button のまま、カードの中の右端に › を置く
- B. `NavigationLink` に戻し、iOS が付ける › をそのまま使う

2. 候補カード
- A. 検索の行と同じく、右端に ＋ を出す
- B. › を出す
- C. 今のまま、印を出さない

## トレードオフ

- 1-A は、› がカードの中に入り、カードは横幅いっぱいのまま。0018 の Button で画面を積む作りも変えない。代わりに、› を自分で描く
- 1-B は標準の作りだが、0018 で嫌った「カードの外に › が出て、カードが狭くなる」がまた起きる
- 2-A は、検索の行と同じ印で「この曲で記録する」が分かる。ハートのある曲は、右端に印が 2 つ並ぶ
- 2-B は、iOS では › が「次の画面へ進む」印なので、押すとシートが開く動きと合わない（0052 で検索の行から › を外したのと同じ理由）
- 2-C は変えなくて済むが、押せることが分からないまま

## 選んだ理由

- 1 は A。0018 で嫌ったのは「カードの外に › が出て、カードが狭くなる」ことで、› そのものではなかった。カードの中に置けばそれが起きず、Button で画面を積む作りも変えずに済む
- 2 は A。検索の行と同じ ＋ にすれば、どこから押しても「この曲で記録する」と同じ印で分かる。› は iOS では「次の画面へ進む」印なので、押すとシートが開く動きと合わない（0052 と同じ考え）

## 決めたこと

- 押すと画面へ進む行には ›、押すと記録シートが開く行には ＋ を、行の右端に出す。押しても何も開かない行（曲詳細の記録の行）には印を出さない
- 履歴の行は Button のまま（0018）、カードの中の右端に › を置く。› は VoiceOver では読ませない（行がボタンなので、押せることは伝わる）
- 候補カードは、ハートの右に ＋ を置く。＋ は VoiceOver では読ませない（「この曲で記録します」のヒントがすでにある）

## 見直す条件

- 押せる行の種類が増えたとき（押すと何が起きるかで、› と ＋ のどちらかを選ぶ）
- 右端に印が 2 つ並ぶのが窮屈だと感じたとき
