# 0012. 点数は小数第3位までの任意入力にする

- 2026-10-14 ／ 承認
- 背景：点数はスライダー（0.1 刻み）で入力し、保存時に小数第2位へ丸め、必須だった。DAM などの採点画面は小数第3位まで出るので、見たままの点数を残せなかった。また、採点を入れずに歌うこともあり、点数がない記録も残したい

## 比較した案
- A. 今のまま、小数第2位まで・必須
- B. 小数第3位まで・必須
- C. 小数第3位まで・任意（点数なしは `nil`）

## トレードオフ
- A は今のままで済むが、採点画面の第3位が残らない。採点しなかった日は適当な値を入れることになる
- B は採点画面と同じ桁で残せるが、採点しなかった日に記録できない
- C は点数なしの記録を、履歴・曲詳細・ランキング・平均のすべてで扱う必要がある（`SingingSession.score` を `Double?` にする）

## 選んだ理由
- C。採点画面の値をそのまま残し、点数なしの日も記録できる
- 入力中は千分の一点を単位とする整数（`ScoreDigitInput`）で持ち、`Double` の誤差を入れない。100.000 を超える入力は受け付けない
- 点数なしの記録は、回数には数えるが、平均・ベスト・直近スコア・前回比・点数ランキングには使わない。点数順の並べ替えでは、高い順・低い順のどちらでも末尾にする
- 既存のデータはそのまま読める（`Double` から `Double?` への変更は SwiftData の軽量マイグレーションで足りる。旧バージョンのデータを新バージョンで開けることを確認済み）

## 見直す条件
- 小数第3位まで出ない機種の点数を多く記録するようになったとき
- 点数なしの記録が多く、集計から外すと傾向が見えにくくなったとき
