# 0008. 歌唱記録は 1 枚のシートにまとめ、`RootView` に 1 つだけ置く

- 2026-07-28 ／ 承認
- 背景：仕様では Intent 選択と歌唱記録の入力が別画面（S-004 ／ S-005）だった。また、記録画面を push で出すと、保存後にルートへ戻るとき一覧が一瞬見えるちらつきがあり、iOS 17.0 では `NavigationStack` と `.sheet` を同じ View で使うとシートを閉じた後にナビゲーションが壊れることがあった

## 比較した案
- A. 仕様どおり別画面にし、`NavigationStack` の push で順に進む
- B. 1 枚のシートにまとめ、各タブの中に `.sheet` を置く
- C. 1 枚のシートにまとめ、`RootView`（`TabView`）に 1 つだけ置き、どのタブからも同じシートを開く

## トレードオフ
- A は画面ごとの責務が明確だが、入力の途中で画面が切り替わり、保存後のちらつきとナビゲーションの不具合がある
- B はタブごとに完結するが、`NavigationStack` と `.sheet` が同じ View に並ぶ
- C は `RootView` にシートの状態が集まるので、保存後に履歴を読み込み直す仕組み（`historyReloadTick`）が別に要る

## 選んだ理由
- C。曲名・点数・気分・メモを 1 枚で途切れずに入力でき、保存後はシートを閉じて `selectedTab = .history` にするだけで遷移が終わる。各タブの `NavigationStack` はルートだけにして、`.sheet` と同じ View に並べない

## 見直す条件
- 記録の入力が 1 枚に収まらなくなったとき（写真の読み取り結果の確認など、段階的な入力が必要になったとき）
- iOS 17 の不具合は最低対応 OS を iOS 26 に上げたので前提から外れたが、ちらつきの回避と「どのタブからも同じシート」の利点は残るので、現時点では維持する
