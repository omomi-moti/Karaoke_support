# 0063. レート制限は Cloud Run が足した相手の IP ごとにトークンバケットで数え、`/health` は DB を見ない

- 2026-11-16 ／ 承認
- 背景：#167（Issue 5）で TestFlight の外部テスターに配ると、サーバーの URL はアプリから取り出せる状態になる。今は 2 つの穴がある。`/health` が呼ばれるたびに DB（Neon）に Ping するので、叩かれ続けると Neon の計算が止まらず、無料枠を使い切って月末まで DB が止まる。回数の制限もないので、1 つの相手の連打で、ほかの人の API が遅くなるか止まる。ADR 0051 の 4-B で「Go のミドルウェアで、IP ごとの回数をメモリで数える」と決めてあり（インスタンスは 1 台なので共有の置き場は要らない）、その中身を #168 で決める。URL はアプリから取り出せ、誰でも叩ける前提に立つ（ADR 0051 の 1-A。アプリに埋めた鍵は取り出せるので、守りは URL を隠すことではなく、サーバーのトークンにした）。この ADR は、叩けなくするのではなく、叩かれても DB とお金とほかの人の API を守る中身を決める

## 比較した案

0. 叩ける相手を絞るか
- A. 絞らない（ADR 0051 の 1-A のまま）。回数で守る
- B. Apple の App Attest で、本物のアプリが本物の iPhone から送ったリクエストだけを受け付ける

1. 回数
- A. 1 分 60 回。毎秒 1 回分たまり、ためられるのは 30 回まで（トークンバケット）
- B. 1 分 30 回、ためられるのは 10 回まで
- C. 1 分 120 回、ためられるのは 60 回まで

2. 相手の IP の取り方
- A. `RemoteAddr`（つないできた相手の住所）
- B. `X-Forwarded-For` のいちばん左
- C. `X-Forwarded-For` のいちばん右（Cloud Run が足したもの）。ないときは `RemoteAddr`

3. DB につながるかを確かめる道
- A. `/ready` として外から呼べる形で残す
- B. 外からは呼べなくする

4. 数える仕組みの書き方
- A. `golang.org/x/time/rate` を使う
- B. 標準ライブラリだけで書く

5. 覚えている IP の数が上限に達したとき
- A. 新しい IP は 429 にする
- B. いちばん古い IP を消して入れる

6. iOS で 429 を受けたとき
- A. 今のまま、サーバーの失敗として扱う（「サーバーで問題が起きました。次にアプリを開いたときに、もう一度送ります」）
- B. 回数の制限を表す失敗を足し、文を分ける

## トレードオフ

- 0-A は、作りが要らず、ADR 0051 の考え（URL は隠せないので、トークンと上限で守る）のまま進められる。代わりに、curl やスクリプトからも叩けるので、回数の制限が守りの中心になる。0-B は、本物のアプリ以外からは叩けなくなり、「URL を叩ける状態にしない」に最も近い。代わりに、サーバーに証明を確かめる処理（Apple の証明書のつながりと、リクエストごとの署名）を足す必要があり、Issue 2 のサインインと同じくらいの作業になる。シミュレーターでは使えない。本物の iPhone とアプリを使う相手は止められないので、回数の制限はどのみち要る。0-B の中身は一般的な知識からの見立てで、Apple の文書ではまだ確かめていない
- 1-A は、アプリが設定を開く・サインインするときにまとめて呼ぶ 3〜5 回を何度くり返しても引っかからず、連打は 30 回で止まり、その後は毎秒 1 回しか通らない。1-B は DB を起こす回数がさらに減るが、携帯の回線で IP を共有するテスターが同時に開くと引っかかりうる。1-C は引っかかる心配がほぼないが、止まるまでに DB を起こす回数が倍になる
- 2-A は、Cloud Run では Google の入口の住所になり、全員が同じ IP に見える。全員で 1 つの回数を分け合うことになる。2-B は、相手が自分で書いた値がそのまま残る位置なので、毎回違う値を書けば、いくらでも新しい回数をもらえる。2-C は、Cloud Run が相手の値の後ろに 1 つだけ足す、という振る舞いに頼る。Google の文書で Cloud Run に直接届いたときの形は見つけられず、同じ構成の報告（GitHub の Issue など）からの見立て。ロードバランサーや CDN を前に置いたら、右から何番目かを数え直す必要がある
- 3-A は、デプロイの後に curl 1 回で DB まで確かめられる。代わりに、Neon を起こせる道が外に残り、レート制限を IP ごとにすり抜けられたら無料枠を使える。3-B は、その道がなくなる。デプロイの後は、アプリでサインインして DB まで届くかを見る。なお、トークンを確かめる API（`/v1/me` など）は、でたらめのトークンでも DB を引くので、Neon を起こせる道はレート制限の後ろに残る
- 4-A は、Go のチームが保守し、同時に呼ばれても正しく数え、時刻を渡せるのでテストで時計を差し替えられる。Apple の鍵を取りにいく回数を絞るのに（`internal/appleauth`）もう使っているので、依存は増えない。4-B は、中身を自分で説明できるが、計算とロックを自分で正しく書いてテストする分が増える。どちらでも、IP ごとの表と古いものの掃除は自分で書く
- 5-A は、メモリも DB も守れる。代わりに、攻撃されている間は、初めて来たテスターも弾かれる（アプリは端末だけで動くので、記録は残る）。5-B は、初めて来た人も通るが、消された IP は回数が戻るので、たくさんの IP で来られると制限が効かなくなる
- 6-A は作りが要らず、自動で送るときは次に前に戻ったときに送り直す（ADR 0059 の「やり直して結果が変わりうる失敗」に入る）。普通に使う人はまず当たらない。6-B は文が正確になるが、まず出ない文のために失敗の種類と文が増える

## 選んだ理由

- 0 は A。外部テスターは数人で、お金は ADR 0051 の上限で守れている。App Attest を入れても回数の制限は要るので、まず回数の制限で守り、App Attest は App Store にアカウントを出すときに考える
- 1 は A。普通に使う人は引っかからず、連打は数秒で止まる。テスターは数人なので、IP を共有しても足りる
- 2 は C。書き換えられる位置を使うと、制限そのものが効かなくなる。Cloud Run の振る舞いは、staging で確かめてから入れる
- 3 は B。外の人に配る以上、DB を起こせる道は少ないほうがよい。DB まで届くかは、アプリで確かめれば足りる
- 4 は A。同時に呼ばれたときの正しさは、自分で書くより保守されているものに任せる。もう使っているので依存も増えない。IP ごとの表と掃除は自分で書くので、仕組みは説明できる
- 5 は A。上限に届くのは攻撃されているときだけで、そのときはメモリと DB を守るほうを優先する。記録は端末にあるので、弾かれても失うものはない
- 6 は A。まず出ないうえ、今の文と送り直しの動きで困らない

## 決めたこと

- レート制限は、ルーターの外側に掛け、`/health` を含む全部の道に効かせる
- 相手の IP は、`X-Forwarded-For` のいちばん右の値（なければ `RemoteAddr`）。IPv4 は 1 つの住所、IPv6 は上の 64 ビット（/64）を 1 つの相手として数える。読めない値のときは、1 つの共通の相手として数える
- IP ごとに、毎秒 1 回分たまり、30 回までためられるトークンバケット（`golang.org/x/time/rate`）で数える。超えたら 429 と、次に通るまでの秒数（切り上げ）を `Retry-After` で返し、後ろのハンドラーと DB は呼ばない
- 使われなくなって 10 分たった IP は消す。覚えている IP は 1 万までにし、超えたら新しい IP は 429 にする
- 429 のたびにはログを出さない（Cloud Run のリクエストのログに残る）。アプリのログに IP アドレスを出さない（NFR-2）
- `/health` は DB に触らずに 200 を返す。DB を確かめる道は外に出さない。起動のときにも DB は確かめない（DB が止まっていてもサーバーは起動し、端末だけで動くアプリと同じく、DB を使う API だけが失敗する。NFR-10）
- iOS は変えない。429 は今までどおりサーバーの失敗として扱う
- staging で、毎回違う `X-Forwarded-For` を付けて連打しても 429 になることを確かめてから、この取り方を正とする

## 見直す条件

- App Store（Release）にアカウントとバックアップを出すとき、または回数の制限をすり抜けて叩かれ続けたと分かったとき（0 で App Attest を考える）
- ロードバランサー・CDN・Cloud Armor を前に置くとき（2 の取り方を数え直す）
- インスタンスの上限を 2 以上にするとき（ADR 0051 の見直す条件と同じ。共有の置き場が要る）
- テスターが 429 に当たったと分かったとき（1 の回数と、6 の文）
- でたらめのトークンで Neon が起こされ続けたと分かったとき（認証の前に別の制限を足すか）
