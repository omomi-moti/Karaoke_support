# 0025. 記録シートと保存直後のシートは、`RootView` の 1 つのシートで切り替え、閉じ終わってから次を出す

- 2026-10-24 ／ 承認
- 背景：保存直後に次の 1 曲を出すシート（[0024](0024-recommend-right-after-save.md)）を足す。[0008](0008-single-recording-sheet-on-root.md) は、記録シートを `RootView` に 1 つだけ置き、保存したらシートを閉じて履歴タブへ移るだけで遷移が終わる、と決めていた。保存の後にもう 1 枚出すので、この判断を置き換える

## 比較した案
- A. 履歴タブ（`HistoryRootView`）に、保存直後のシートを別の `.sheet` で置く
- B. 記録シートを閉じずに、同じシートの中身を「保存しました＋候補」に差し替える
- C. `RootView` の 1 つの `.sheet(item:)` で、記録シートと保存直後のシートを切り替える。前のシートが閉じ終わってから（`onDismiss`）次を出す

## トレードオフ
- A は `RootView` を変えずに済むが、`NavigationStack` のあるタブに `.sheet` が並び、0008 で避けた形に戻る。保存直後のシートのカードから記録シートを開くとき、別の場所にある 2 つのシートを行き来することになる
- B はシートを閉じて開く動きがなく滑らかだが、履歴に記録が増えたことが見えない。記録シートの中に、別の画面の状態を持ち込むことになる
- C は `RootView` にシートの切り替えの状態（`pendingSheet`、`isDismissingSheet`）が増える。閉じている途中に次のシートを出すと SwiftUI が出し損ねることがあるので、閉じ終わるのを待つ仕組みが要る

## 選んだ理由
- C。0008 の「シートは `RootView` に 1 つ、どのタブからも同じ」をそのまま保てる。保存直後のシートからカードで記録シートへ移るときも、同じ仕組みで切り替えられる
- 開き方はすべて `present()` を通す。シートが出ていなければその場で出し、閉じている途中なら閉じ終わってから出し、別のシートが開いていれば閉じてから出す
- 閉じている途中にもう一度押されたとき（カードの二度押しなど）は、次のシートを予約し直すだけにし、閉じ終わってから 1 枚だけ出す。閉じている途中に出そうとすると、上の「出し損ね」がそのまま起きるため
- 保存したら、0008 と同じく記録シートを閉じて `historyReloadTick` を増やし、履歴タブへ移る。そのあと候補を読み、あれば保存直後のシートを出す。候補の読み込みが閉じ終わるより先に終わったときは、閉じ終わるのを待ってから出す
- 候補を待っている間に、別のシートが開かれた・開く予約が入ったとき（保存した直後に＋を押した、など）は、保存直後のシートは出さない。後から届いた候補で、入力し始めた記録シートを閉じないため。記録が増えて候補の読み込みが遅くなるほど起きやすくなる（[0029](0029-recompute-track-stats-without-cache.md)）
- シミュレーターで、保存 → 保存直後のシート → カード → 記録シート、の切り替えで取りこぼしがないことを確かめた（2026-10-24）

## 見直す条件
- 保存直後のシートが急に出る、と感じられるとき（間をあける、B の差し替えにする、など）
- シートからシートへ移る経路がさらに増え、`RootView` の切り替えが追いにくくなったとき
