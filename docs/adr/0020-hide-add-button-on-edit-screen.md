# 0020. 編集画面では＋ボタンを、画面から PreferenceKey で伝えて隠す

- 2026-10-16 ／ 置き換え済み（→ [0022](0022-open-edit-in-root-sheet.md)）
- 背景：新規記録の＋ボタンは `RootView` が選曲・履歴タブの上に重ねて表示している。履歴から開いた編集画面の上にも出て保存ボタンに重なり、押すと編集中に新規記録が始まっていた

## 比較した案
- A. 履歴で画面を 1 つでも開いたら（曲詳細も含めて）＋ボタンを隠す
- B. 編集画面が PreferenceKey で「隠して」と伝え、＋ボタンの側が受け取って隠れる
- C. `RootView` から「隠す・出す」を切り替える関数を Environment で渡し、編集画面が表示・非表示のときに呼ぶ
- D. ＋ボタンをタブの外に 1 つだけ置き直し、そこで隠すかどうかを決める

## トレードオフ
- A は仕組みが単純だが、曲詳細でも＋ボタンが消える。曲詳細の＋で曲名を入れて記録を開く予定があるので困る
- B は編集画面だけで隠せ、画面を閉じれば自動で元に戻る。合図が画面遷移（NavigationStack）の外まで届くかの確認が要った（シミュレータで届くことを確認した）
- C は確実に届くが、表示・非表示のときに呼ぶ処理が要り、呼び忘れや戻し忘れで＋ボタンが消えたままになりうる
- D はタブを切り替えたときの＋ボタンのちらつき（＋ボタンがタブごとにあり、出し直されるたびに Liquid Glass の表示アニメーションが走る）も同時に直せるが、設定・検索タブで隠す処理も要り、編集モードの変更としては大きい

## 選んだ理由
- B。編集画面だけで隠せて、戻し忘れが起きない。曲詳細の＋ボタンは残せる
- 合図は記録シートの本体（`RecordingSheetContentView`）から出しているので、記録を読み込み中の一瞬と、読み込みに失敗したときの画面では＋ボタンが出たままになる。押しても新規記録のシートが開くだけでデータは壊れないので、今回は受け入れた

## 見直す条件
- タブ切り替えのちらつきを直すために D に移るとき（合図を受け取る場所を `RootView` に移す）
- 読み込み中・失敗の画面でも＋ボタンを隠す必要が出たとき（合図を `RecordingSheetContainerView` から出す）
