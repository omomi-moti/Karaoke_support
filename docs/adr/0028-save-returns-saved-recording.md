# 0028. 記録シートの `save()` は、成否と保存した記録の要約を 1 つの値（`SavedRecording?`）で返す

- 2026-10-24 ／ 承認
- 背景：保存直後のシート（#115）に、保存した記録の曲名・気分・点数を渡す必要ができた。最初は `save()` の戻り値の `Bool` を残し、要約をプロパティ（`lastSavedRecording`）で返したが、成否と要約が別々になり、2 つがずれる余地があった

## 比較した案
- A. 戻り値は `Bool` のまま、要約はプロパティで返す
- B. A に加えて、View で「成功したのに要約がない」ときに `assertionFailure` で止める
- C. 戻り値を `SavedRecording?` にする（保存しなかった・失敗したときは `nil`）

## トレードオフ
- A は既存のテストを変えずに済む。ただ、将来 `save()` に要約を入れずに `true` を返す経路を足すと、記録は保存されたのにシートが閉じない。エラーも出ないのでユーザーはもう一度押し、再試行用の id（`pendingSessionIdForSave`）は成功したときに消えているので、新しい id で保存されて同じ記録が 2 件になる（[0006](0006-idempotent-save-in-ui-and-data.md) の二重保存）。入れ忘れはコンパイラもテストも見つけられない
- B は 1 行で済むが、気づけるのは開発中にその経路を実際に通したときだけで、リリースでは A と同じ
- C は既存のテストで戻り値を見ている 9 か所を書き換える必要があるが、要約なしで成功を返す書き方そのものができなくなり、入れ忘れはコンパイルエラーになる

## 選んだ理由
- C。払うのは 1 回だけの機械的な書き換えで、二重保存につながる種類の不具合を型で起きなくできる
- 「成功したら、別の場所に結果が入っているはず」という暗黙の決まりがなくなり、View は `guard let saved = await viewModel.save()` の 1 行で済む。失敗した後も古い要約が残り続けるプロパティもなくなる
- 編集のときも要約を作る（今は使わない）が、値をまとめるだけなのでコストはほぼない

## 見直す条件
- 保存の結果として、要約以外のこと（保存はできたが注意が要る、など）を返す必要が出たとき。`Result` や専用の enum を検討する
