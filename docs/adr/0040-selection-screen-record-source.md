# 0040. 選曲画面から付けた記録は、保存直後の提案とは別の入口として数える

- 2026-10-27 ／ 承認
- 背景：選曲MVP のスプリント 4（#126）。選曲画面のカードから記録シートを開けるようにする。記録には入口（`RecordSource`。今は `manual` と `suggestion`）を持たせていて（[0034](0034-record-source-as-optional-enum.md)）、確かめたい仮説は「保存した直後に過去の曲を見せれば、次の 1 曲が決まる」。選曲画面から付けた記録を、どの入口として数えるかを決める

## 比較した案

- A. `RecordSource` に `selectionScreen` を足し、保存直後の提案（`suggestion`）とは分けて数える
- B. 保存直後の提案と同じ `suggestion` として数える
- C. 自分で選んだ記録（`manual`）として数える

## トレードオフ

- A は、保存直後の提案から選んだ数と、選曲画面から選んだ数を別々に見られる。仮説（保存した直後に見せれば決まる）を、選曲画面の分と混ぜずに確かめられる。enum の case が 1 つ増えるが、保存するのは文字の値で、空を許す項目のままなので、DB の形は変わらない
- B は case が増えず、設定の「提案から記録した数」に選曲画面の分も入る。保存直後のシートが効いたのか、選曲画面が効いたのかを見分けられなくなる
- C は何も足さずに済むが、選曲画面が使われたかが記録に残らない

いずれの案でも、曲を書き換えて保存したら `manual` にする（0034 と同じ）。設定の「テストへのご協力」の数は、今までどおり `suggestion` だけを数え、分母の「入口を記録し始めてからの記録の数」には `selectionScreen` も入る

## 選んだ理由
- A。確かめたい仮説は「保存した直後に見せれば決まる」なので、保存直後のシートから選んだ数は、選曲画面の分と混ぜずに見たい
- 選曲画面から選ばれたかも記録に残しておけば、あとで選曲画面がどれだけ使われたかも数えられる。case を 1 つ足すだけで、DB の形は変わらない

## 見直す条件

- 選曲画面から選んだ数も、設定や TestFlight での測り方に入れたくなったとき
- 保存直後のシートと選曲画面を、1 つの入口として見た方がよいと分かったとき
