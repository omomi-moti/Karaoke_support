# 0023. ＋ボタンはガラスのまま、ライト・ダーク共通の濃いめのピンクにし、大きさは固定にする

- 2026-10-23 ／ 承認
- 背景：＋ボタンは「今歌った 1 曲を、どの画面からでも迷わず記録し始めるための、ただ 1 つの入り口」（X 型。種類は選ばせない）。ダークモードで白い＋と背景の比が 2.96:1 しかなく、見た目（ガラスか単色か）と大きさも決めていなかった

## 比較した案
- 見た目：A. `.glassProminent` に色を付ける ／ B. 単色で塗る
- 色：今の AccentColor（ダーク 2.96:1）／ (214, 38, 104) ／ (196, 24, 86)
- 大きさ：固定 ／ 文字の大きさの設定に合わせる

## トレードオフ
- ガラスは HIG（浮かぶ大事な操作に色付きのガラス）に合い、押したときの反応もシステムが付ける。縁が後ろの画面を映すので、Slack のように 1px も変わらない見た目にはならない。単色は背景で色が変わらないが、HIG から外れ、押したときの見た目を自分で作る必要がある
- ガラスを通すと色が明るく見える（赤 +10・緑 +24・青 +18 ほど）。(214, 38, 104) は実際の見え方で 4.06〜4.14:1 に下がり、4.5:1 に届かなかった
- 大きさを文字の設定に合わせると HIG に沿うが、＋の位置と一覧の下の余白が設定で変わる

## 選んだ理由
- ガラスのまま、色は (196, 24, 86) をライト・ダーク共通で使う（`AppAddButton`）。実際の見え方で白い＋との比は 4.71〜4.92:1、背景との差はダーク約 3.7:1・ライト 4.8:1
- 大きさは 48pt（印は 20pt）で固定。タップに要る 44pt は満たしている。印の見やすさはコントラストで確保する
- 寸法は `AddRecordingButtonMetrics` にまとめ、一覧の下の余白（`addRecordingButtonClearance()`）も同じ値から出す

## 受け入れたこと
- 色の比はシミュレーターで測った（4.71〜4.92:1）。実機でも、ライト・ダークとも見えにくくないことを確かめた。「コントラストを上げる」「透明度を下げる」の設定では未確認
- 実機の録画で、＋の縁の色の中心が、タブによって約 2pt ずれて見えた（それぞれのタブにいる間は動かない）。ガラスが後ろの画面を映すためと見ている。Slack の不透明な＋では起きない
- 実機で選曲⇄履歴を素早く連打すると、1 コマ（約 18ms）だけ＋を含む画面が真っ黒になる。約 1 秒おきの切り替えでは 384 コマ中 0 だったので後回しにした。選曲タブが表示のたびに読み込み直していることが原因と見ているが、未確認

## 見直す条件
- iOS の更新で Liquid Glass の描き方が変わったとき（比を測り直す）
- 文字を大きくしたときに＋が見づらいという声が出たとき

## ＋を出す画面を増やすとき
- `RootView` の `isAddButtonVisible` にタブを足す
- スクロールする画面なら `addRecordingButtonClearance()` を付ける
