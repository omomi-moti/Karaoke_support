# 0036. 「また歌いたい」はハートとして記録に持たせ、空はハートなしとして読む

- 2026-10-26 ／ 承認
- 背景：選曲MVP のスプリント 3（#124）。点数だけでは「また歌いたい曲」は分からないので、歌った直後にハートを 1 タップで付けられるようにし、次からの提案で上に出す。ハートは記録（`SingingSession`）の項目で、編集でも変えられる。項目を足すときは空を許す形で足す決まりがある（[ADR 0034](0034-record-source-as-optional-enum.md)）ので、前からある記録のハートは空（`nil`）になる

## 比較した案

データの持ち方（空と `false` の扱い）

- A. 空を許す `recordedWantAgain: Bool?` に保存し、読むときは空も `false` も「ハートなし」とする。編集で更新するときは、画面の値を毎回書き込む
- B. A と同じく空を許して保存するが、編集で更新するときは、ハートを変えたときだけ書き込む。前からある記録は、ハートを触らずに編集すれば空のまま残る

## トレードオフ

- A は更新の処理が単純で、ほかの項目（気分・日時・点数・メモ）と同じく「画面の値をそのまま書く」で済む。前からある記録は、編集すると空から `false` に変わるので、DB の中で「ハートを付けられるようになる前の記録」と「ハートを付けなかった記録」を見分けられなくなる
- B は空が「ハートを付けられるようになる前の記録」の印として残り、入口（`recordedSource`）と同じように、機能ができてからの記録だけを数えられる。その代わり、更新の処理で「変えたかどうか」を見る分岐が要り、編集を開いたときの値を覚えておく必要がある
- ハートは提案の並び順にだけ使い、並び順では空も `false` も同じ「ハートなし」として読むので、どちらの案でも画面の結果は変わらない。違いが出るのは、将来「ハートを付けられるようになってからの記録のうち、何割にハートが付いたか」を数えるときだけ

## 選んだ理由
- A。ハートは提案の並び順にだけ使い、空と `false` を同じ「ハートなし」として扱っても、画面の結果は変わらない。ハートを付けた割合を数える予定もないので、空を印として残す意味が今はない
- 更新の処理は、ほかの項目と同じく「画面の値をそのまま書く」にそろえ、分岐を増やさない。数えたくなったときに B へ変えればよい

## 見直す条件
- ハートを付けた割合など、ハートを付けられるようになってからの記録だけを数えたくなったとき（B に変える）
