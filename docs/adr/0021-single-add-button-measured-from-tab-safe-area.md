# 0021. ＋ボタンは `RootView` に 1 つだけ置き、タブバーの高さはタブの中身の安全領域から測る

- 2026-10-23 ／ 承認
- 背景：新規記録の＋ボタンを選曲・履歴タブの中身にそれぞれ置いていたため、タブを切り替えるたびに別のボタンに入れ替わり、切り替えの演出で一瞬暗くなったり約 2pt 揺れたりしていた（実機の録画をコマ送りして確認）。＋をタブの外に 1 つだけ置くと、＋の位置からはタブバーの高さが分からないので、その取り方を決める必要があった

## 比較した案
- A. 選曲・履歴タブの中身で下の安全領域（タブバー＋ホームインジケーター）を `onGeometryChange` で測り、`RootView` に置いた＋の位置に使う
- B. タブバーの高さを数字で決め打ちする
- C. UIKit の `UITabBarController` の `tabBar.frame` を読む

## トレードオフ
- A は決め打ちの数字がなく、機種や OS の更新でタブバーの高さが変わっても、システムが返す安全領域に合わせて動く。ただし一度描いてから測って置き直すので、測るまでの最初のコマは位置が決まらない
- B は一番簡単だが、iOS 26 でタブバーが浮く形に変わったように、OS の更新でずれる
- C は Auto Layout でタブバーの上端につなげられ、測る必要もない。ただ SwiftUI の `TabView` が中で `UITabBarController` を使うかは Apple が約束していない内部の作りで、覗き込むと OS の更新で壊れうる。確実にやるなら `TabView` をやめてタブを UIKit で作り直すことになる

## 選んだ理由
- A。SwiftUI の `TabView` では、タブバーの位置はタブの中身の安全領域からしか分からない。システム自身が返す値なので、決め打ちより壊れにくい
- 測るまでは＋を出さない（`tabBarInset > 0` になるまで透明）。キーボードの分は含めない（`ignoresSafeArea(.keyboard)` にした背景で測る）
- 検索・設定タブでは＋を外さずに透明にし、押せない・読み上げないようにする。外すと戻るたびに作り直しになり、Liquid Glass の出てくる動きがまた走る
- シミュレーターで、選曲 ⇄ 履歴を素早く切り替えても＋の位置と色が 1 コマも変わらず、検索タブでは一瞬で消えることを確かめた。Slack の＋（ホーム・DM で同じ位置と色のまま、出さないタブでは一瞬で消える）と同じ動きになった

## 見直す条件
- タブバーが小さくなる（`tabBarMinimizeBehavior(.onScrollDown)`）ときに、＋の動きが遅れて気になるとき
- SwiftUI にタブバーの位置を直接取れる API が増えたとき
- タブを UIKit で作り直すことになったとき
