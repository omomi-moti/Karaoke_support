# 0035. 文書は AI 向けのものも含めて日本語で書き、識別子・コマンド・ファイル名は英語のままにする

- 2026-10-26 ／ 承認
- 背景：CLAUDE.md は最初に `/init` で自動生成したときに英語で作られ、そのあと足した `.claude/rules/` も英語で書いた。一方、憲法・ADR・docs・レビューのスキル・Issue・コミットは日本語で、方針がないまま英語と日本語が混ざっていた。本人は、書くことは AI に任せつつ、変更を理解してコードの質を保ちたい（CLAUDE.md の「Claude との作業の約束」）

## 比較した案
- A. 文書は全部日本語で書く。コードの識別子・コマンド・ファイル名は英語のまま
- B. AI だけが読む文書（CLAUDE.md・`.claude/rules/`）は英語、人が読む文書（ADR・docs・スキル）は日本語
- C. 文書は全部英語で書く

## トレードオフ
- A は本人がすべての文書を読み、直し、持ち主でいられる。ADR や docs と言葉がそろい、CLAUDE.md から ADR を参照しても行き来しやすい。毎回読み込まれる CLAUDE.md は、英語より多くトークンを使う（約 120 行なので、増える量は文脈全体から見ればわずか）
- B は毎回読み込まれる分のトークンが少し減る。本人が CLAUDE.md やルールをレビューするときに英語を読むことになり、「ADR 0034」と書いてあっても本体は日本語、という行き来が残る。どの文書がどちらの言葉かを覚えておく必要がある
- C はほかの人やツールと共有しやすいが、今は一人で日本語で使っており、本人が読む手間が増える。今ある日本語の文書を全部書き直す必要もある
- AI が指示を守るかどうかは、日本語でも英語でも大きくは変わらない（言葉の違いで差が出るという公式の根拠は見当たらない）

## 選んだ理由
Aを選んだ理由は自分自身がすぐにレビューできたり、すぐ読めたりすることが一番重要だと考える。英語にすることでの精度の向上や、トークンの使用量に関しては個人利用に関してはそこまで影響が出るくらいではないと考えています。

## 見直す条件
- ほかの人と一緒に開発することになり、その人が日本語を読まないとき
- CLAUDE.md が大きくなり、毎回読み込まれるトークンが気になるようになったとき
