# 0048. 端末を超えて記録を残すために自前のサーバーを入れ、Go と Docker で作って Cloud Run と Neon に置く

- 2026-11-02 ／ 承認
- 背景：記録は端末の SwiftData にしかなく、アプリを入れ直したり機種を変えたりすると残らない。端末を超えて記録を残したい（C1）。あわせて MusicKit で曲名の入力を助けたい（M1）。1 日 1.5 時間 × 2 週間ほどで MVP を作る。App Store に出すのは MVP に入れないので、MVP の間にサーバーを使うのは自分だけ

## 比較した案

1. クラウドに記録を置く方法
- A. SwiftData の CloudKit 同期（本人の iCloud に置く）
- B. 自前のサーバーを作る

2. サーバーの言語と置き場所
- A. Go（標準の `net/http` と `pgx`）と Docker で作り、Cloud Run（GCP）に置く。DB は Neon の Postgres
- B. TypeScript で作り、Cloudflare Workers に置く。DB は D1（SQLite）か、Hyperdrive で Neon につなぐ
- C. Go と Docker で作り、Fly.io に置く
- D. Go と Docker で作り、Render に置く
- E. Go と Docker で作り、AWS（ECS Fargate と RDS）に置く
- F. Go と Docker Compose で作り、VPS に置く

3. 環境
- A. 手元（local）と staging だけにし、本番は App Store に出す準備のときに足す
- B. 最初から local・staging・本番の 3 つを作る

## トレードオフ

- 1-A はサーバーもログインも要らず、21 時間で C1 と M1 の両方が入る。ただし `@Attribute(.unique)` を外す・関係を空を許す形にするなどモデルの直しが要り、スキーマを本番に出した後は項目を消せない。サーバー側の作業は学べない
- 1-B はログイン・API・DB・デプロイを自分で作るので、C1 だけで 17〜18 時間かかる。代わりに、サーバーサイドの作り方を一通り学べ、データの持ち方も自分で決められる
- 2-A は月 0 円の無料枠に収まり、HTTPS とログが付いてくる。Go なら止まった後の最初の 1 回の待ちは 1 秒前後。Dockerfile・Postgres・接続プールなど、どこのサーバーでも通じる形が身につく。GCP のプロジェクトと権限に慣れる手間があり、クレジットカードの登録が要る
- 2-B は立ち上げが最も軽く（`wrangler deploy`）、月 0 円で、待ちもほとんどない。全体で 3〜4 時間早い。ただし Go は書けず、リクエストごとに動く Cloudflare 独自の形で、Cloudflare の外ではあまり通じない。Go で使うには Cloudflare Containers（有料のプラン）か Wasm が要り、Workers の良さが消える
- 2-C は立ち上げが軽いが、新しく使う人向けの無料枠がなくなっていて、月に数ドルかかる見込み
- 2-D は GitHub をつなぐだけで始められるが、無料だと止まった後の最初の 1 回に数十秒かかり、無料の Postgres には期限がある
- 2-E は業界で最も使われている構成そのものだが、ネットワーク・ロードバランサー・権限を全部組む必要があり、立ち上げだけで MVP の時間の多くを使う。ロードバランサーと RDS で月に数千円かかる
- 2-F は Linux・nginx・HTTPS の証明書まで学べるが、学ぶ中心が Go でサーバーを作ることから Linux の運用に移り、セキュリティの更新を自分で続ける責任が残る。月 500〜1000 円
- 3-A は作る環境が少なく、試しのデータを本物のように扱わずに済む。本番を足すときに、デプロイの手順をもう一度通す必要がある
- 3-B は後で足す手間がないが、MVP の間は使う人がいない本番を保つことになる

料金と無料枠は 2026-11 の時点で確かめておらず、Issue 1 の最初に確かめる。

## 選んだ理由

- 1 は B。サーバーサイドをやりたい。CloudKit のほうが早いが、サーバーを自分で作ることがこの MVP の目的の 1 つ
- 2 は A。App Store に出すのを MVP から外したので、今は速く届けることより学ぶことを優先する。そうなると Workers の速さ・安さ・待ちのなさは今は効かず、Go を書けることと、どこでも通じるサーバーの形が身につくことのほうが大きい。はじめから Go を使いたかった。Workers との差は 3〜4 時間で全体の 1 割ほどに収まり、2 台の同期（C2）でトランザクションやテーブルを設計するときも、普通の Postgres のほうが素直に書ける。コンテナにしておけば、合わなかったときに Fly.io や AWS へ 1〜2 時間で移せる
- 3 は A。MVP の間にサーバーを使うのは自分だけになる。Neon はブランチで DB を分けられるので、本番は後から足せる

## 見直す条件

- 早く App Store に出して使う人に届けたくなったとき、または GCP の画面や権限で何時間も詰まったとき（2 を B か C にするかを考える）
- 無料枠を超える費用が出たとき、または Cloud Run の最初の 1 回の遅さで困ったとき（2 を見直す）
- 仕事で AWS を使うことになったとき、または Linux やネットワークの中身まで学びたくなったとき（2 を E か F にするかを考える）
- App Store に出す準備を始めるとき（3 の本番を足す）
- サーバーを保つ手間が、学ぶことの価値を上回ったとき（1 を A に戻すかを考える）
