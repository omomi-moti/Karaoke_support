# 0007. enum を含む `#Predicate` を使わず、メモリで絞り込む

- 2026-07-28 ／ 承認（見直し候補）
- 背景：`#Predicate<SingingSession> { $0.intent == .shout }` はコンパイルが通るが、iOS 17.0〜17.2 の実機で実行時エラーになるケースがあった

## 比較した案
- A. enum を `#Predicate` でそのまま比較する
- B. RawValue（String）の比較に書き換える
- C. 直近の一定件数を `fetchAll` で取り、メモリ上で `filter` する

## トレードオフ
- A は iOS 17.0〜17.2 で落ちる
- B は `#Predicate` の型推論とぶつかって安定しなかった
- C は確実に動くが、DB で絞り込めないので、直近の件数より前の記録は Intent で絞り込んでも出てこない

## 選んだ理由
- C。落ちないことを優先した。同じ Intent でページを足すときは `intentFilterCache` で再取得を抑えている
- 曲ごとの記録の取得（`fetchSessions(trackId:)`）も、リレーションを使った述語を避けて同じ方針にしている

## 見直す条件
- 最低対応 OS が iOS 17.3 以降になったとき
  - **2026-09-23 に最低対応 OS を iOS 26 に上げたので、この条件は満たしている。** DB 側での絞り込みに戻すか、iOS 26 で `#Predicate` が安定して動くかを確認してから新しい ADR で決める
