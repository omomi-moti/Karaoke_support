# 0060. バックアップのオン・オフはスイッチにせず、オンにする行とオフにするボタンで行う

- 2026-11-15 ／ 承認
- 背景：#161 の手順 3 で、設定のバックアップの欄にスイッチを置き、オンにするときは同意の画面へ進むようにした。実機で試すと、スイッチがオンに動きかけてすぐオフに跳ね返り、そのまま別の画面に進むので、動きが分かりにくかった。HIG では、スイッチは押した時点で状態を切り替えるものとされている。オンにする前に同意の画面を見せる（ADR 0058 の 2-B）ので、スイッチを押した時点ではオンにできない

## 比較した案

- A. オフのときは「バックアップをオンにする」の行（右に ›）を置き、同意の画面へ進んで「オンにする」を押す。オンのときは「バックアップをオフにする」のボタン（赤）を置き、件数を見せて確認してから消す
- B. iCloud バックアップと同じく、「バックアップ」の行から専用の画面に進み、そこに説明とスイッチを置く。スイッチをオンにしたら同意とする
- C. 今のまま、スイッチを押したら同意の画面へ進む

## トレードオフ

- A は、進む行とすぐ効くボタンに分かれるので、どちらも標準の使い方になる。同意は今のまま「オンにする」を押すことで、ADR 0058 の決めたことは変わらない。代わりに、オンかオフかを 1 つのスイッチで一目では見られず、行とボタンのどちらが出ているかで見る
- B は、iOS の設定の作りに近く、説明とスイッチが同じ画面にあるので、スイッチを押した時点でオンにできる。代わりに、同意が「スイッチをオンにすること」になり、「オンにする」を押して同意とする #161 と ADR 0058 の書き方から外れる。画面も 1 つ増える
- C は作り直しが要らないが、スイッチが跳ね返ってから画面が進む動きが残る

## 選んだ理由

- A。スイッチは押したらすぐ効くものなので、押した後に同意の画面へ進ませたり、跳ね返らせたりしない。同意は今までどおり「オンにする」を押すことにし、ADR 0058 の決めたことを変えずに済む形を選んだ

## 見直す条件

- テスターから、オンかオフかが分かりにくいと言われたとき
- 同意の取り方を変えるとき（スイッチで同意を取ってよいと決めたら B を考える）
