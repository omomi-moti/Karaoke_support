# 0041. 「歌い切れたか」は空を許す形で記録に持たせ、空は歌い切れたとして読む

- 2026-10-27 ／ 承認
- 背景：選曲MVP のスプリント 5（#128）。記録シートで「歌い切れた？」（歌い切れた／歌い切れなかった）を残し、歌い切れなかった曲を提案から外す。「歌い切れたか」は記録（`SingingSession`）の項目にする。項目を足すときは空を許す形で足す決まりがある（[0034](0034-record-source-as-optional-enum.md)）ので、前からある記録は空（`nil`）になる。元の仕様では「既存の記録は歌い切れた扱い」としている

## 比較した案

1. データの持ち方（空の扱い）
- A. 空を許す `recordedIsCompleted: Bool?` に保存し、読むときは空を「歌い切れた」とする。編集で更新するときは、画面の値を毎回書き込む（[0036](0036-want-again-heart.md) のハートと同じ形）
- B. A と同じく空を許して保存するが、編集で更新するときは、変えたときだけ書き込む。前からある記録は、触らずに編集すれば空のまま残る

2. 編集で変えられるか
- A. 変えられる
- B. 変えられない（歌った直後だけ付けられる）

## トレードオフ

- 1-A は更新の処理が単純で、ほかの項目と同じく「画面の値をそのまま書く」で済む。前からある記録は編集すると空から `true` に変わり、DB の中で「付けられるようになる前の記録」と「歌い切れた記録」を見分けられなくなる
- 1-B は空が「付けられるようになる前の記録」の印として残るが、更新の処理に「変えたかどうか」を見る分岐が要る
- 2-A は付け間違いを後から直せる。提案は最新の記録で決めるので、最新ではない記録を変えても提案は変わらない
- 2-B は「歌った直後の手応え」だけが残るが、付け間違いを直せない

## 選んだ理由

- 1 は A。ハート（0036）と同じ形にそろえる。提案では空も `true` も同じ「歌い切れた」として読むので、画面の結果は変わらない。付けられるようになってからの割合を数える予定もない
- 2 は A。ハートと同じく、付け間違いを後から直せる方がよい

## 見直す条件

- 「歌い切れなかった」を付けた割合など、付けられるようになってからの記録だけを数えたくなったとき（1 を B に変える）
