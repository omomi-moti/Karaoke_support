# 0005. 履歴は値型のスナップショットで持つ

- 2026-07-28 ／ 承認
- 背景：一覧の行に SwiftData の `SingingSession` を直接渡すと、削除後に SwiftUI が古い参照を描画して fault で落ちることがある

## 比較した案
- A. `SingingSession` をそのまま ViewModel に持ち、一覧に渡す
- B. 取得した直後に値型（`HistorySessionRowDisplayItem`）に写して持つ

## トレードオフ
- A は写す手間がないが、削除のタイミングで落ちうる。楽観的な更新もしにくい
- B は写すコードが要るが、削除後も安全に描画できる

## 選んだ理由
- B。落ちないことを優先した。あわせて次のことができる
  - 削除は先にスナップショットから消し、DB の削除に失敗したら戻す（楽観的な更新）
  - 並べ替えや絞り込みをメモリ上で完結でき、再取得が要らない
  - 一覧で持つのは最大 500 件にして、記録が多い人でもメモリを抑える
- 曲詳細も同じ理由で `TrackScoreTrendPoint`（値型）に写している

## 見直す条件
- SwiftData の削除と SwiftUI の描画のずれで落ちる問題が解消されたとき
