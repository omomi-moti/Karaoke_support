# 0047. 曲詳細から記録を直し・消し、＋でその曲を記録できるようにする

- 2026-10-28 ／ 承認
- 背景：App Store に出す前の直し（#135）。今の曲詳細は見るだけで、記録を直したり消したりするには、履歴に戻って同じ記録の行を探す必要がある。曲詳細を見て「もう一度歌おう」と思っても、＋で開いた記録シートに曲名を打ち直す必要がある（ADR 0020 のときから、曲詳細の＋で曲名を入れて記録を開くことは考えていた）

## 比較した案

1. 曲詳細から記録を直す・消す方法
- A. 記録の行を押すと編集シートが開き、編集シートのいちばん下に「この記録を削除」（確認付き）を足す
- B. 履歴と同じく、記録の行を右へスワイプで「編集」、左へスワイプで「削除」（ADR 0046 の確認付き）にする

2. 曲詳細から記録を始める方法
- A. 右下の＋を、曲詳細にいるときだけ「その曲名を入れて開く」にする
- B. 右下の＋は今のまま空で開き、曲詳細の中に「この曲を記録する」ボタンを置く

3. 曲詳細の＋で開くときの気分と入口
- A. 気分は決めずに開き（空で開く＋と同じ初期値）、入口は手で付けた記録（`manual`）にする
- B. その曲の前回の気分を入れて開き、「曲詳細から」という入口を新しく足す

## トレードオフ

- 1-A は今の画面の作り（`ScrollView`）のまま足せて、履歴からも同じ編集シートで消せるようになる。ただ、履歴はスワイプ、曲詳細は行を押す、と同じ記録の操作が画面で変わる
- 1-B は履歴と操作がそろうが、スワイプは `List` の中でしか使えないので、曲詳細を `List` に作り直す必要がある（見た目は今と同じに保つ）
- 2-A は＋が 1 つのままで、画面に新しいボタンが増えない。＋は `RootView` に 1 つしかないので、今どの曲の詳細にいるかを知る必要がある。履歴タブの画面の積み方を `RootView` に持たせて読めば、画面から合図を送らずに分かる（ADR 0020 の PreferenceKey のような仕組みはいらず、ADR 0022 で消した仕組みは戻らない）。そのために、積み方を中身を読めない `NavigationPath` から、`[HistoryRoute]` に変える。＋の見た目は変わらないので、押すまで曲名が入ることは分からない
- 2-B は作りが単純だが、試すと、横いっぱいのボタンが直近スコアと張り合い、すぐ下の＋と＋が 2 つ並んで見えた
- 3-A は空で開く＋と同じ記録になり、入口の数え方（ADR 0034・0040）を変えなくてよい。気分は自分で選ぶ
- 3-B は 1 回押す手間が減るが、前回の気分に引っ張られやすい。入口が増えると、設定の「テストへのご協力」の数え方も見直しが要る

## 選んだ理由

- 1 は B。履歴と曲詳細で記録の操作がそろっていないと、こんがらがる。直したり消したりしたら、曲詳細と後ろの履歴の両方を読み直し、その曲の記録が 0 件になったら履歴に戻る
- 2 は A。はじめ B を作って試したが、ボタンがそのまますぎてスマートでなかった。ボタンを増やさず、いつもの＋で入れるほうがよい。シートの曲名は書き換えられるので、違う曲を記録したいときも困らない
- 3 は A。保存直後の提案のように前回の気分を入れると、その曲の前回の気分に引っ張られる。入口の数え方は、提案と選曲画面だけを分けて数えているので、曲詳細からの記録は手で付けた記録と同じに数える

## 見直す条件

- 曲詳細の＋で曲名が入ることに気づかない、または空で開きたいのに困ると言われたとき（2 を見直す）
- Spotify の曲を使うようになったとき（ルートの曲名は表示用なので、曲の情報をルートに持たせる）
- 曲詳細からの記録を、入口として分けて数えたくなったとき（3 を B にする）
