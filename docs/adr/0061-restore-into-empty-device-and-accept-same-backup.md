# 0061. 取り込みは空の端末でサインインの直後に聞き、同じ中身の送り直しは成功として扱う

- 2026-11-16 ／ 承認
- 背景：Issue 4 で、記録のない端末にサーバーのバックアップを取り込めるようにする（FR-5、ADR 0049 の 5-A）。取り込むかを聞く場所・おかしな値の扱い・取り込んだ後のバックアップのオン・オフを決める。あわせて、Issue 3（#161）で見つけた穴を直す。`PUT /v1/backup` がサーバーでは成功したのに、iOS が返事を受け取る前に止まると、端末は新しい版を覚えず、次の送信が 412 になる。端末が 1 台でも「ほかの端末から送ったバックアップと食い違っています」と出て、自動の失敗は画面に出さないので、本人が設定を開いて確かめるまでバックアップが止まる。ADR 0058 はこの場合を考えていない。2026-11-15 に実機で起きたと見ているが、確かめてはいない

## 比較した案

1. 取り込むかを聞く場所
- A. サインインした直後に、端末が空でバックアップがあれば、聞かずに自動で取り込む
- B. サインインしていて、端末が空でバックアップがある間だけ、設定のバックアップの欄に「バックアップから取り込む」の行を出す。押したら件数を見せて確認する
- C. サインインした直後に、端末が空でバックアップがあれば 1 回聞く（「取り込む」／「取り込まずに新しく始める」）。取り込まなかった人には、端末が空の間、B の行も残す

2. 値がおかしい記録があったとき
- A. 1 件でもあれば、何も取り込まない
- B. おかしい記録だけを飛ばして、残りを取り込む

3. 取り込んだ後のバックアップ
- A. オフのまま。取り込んだ控えの版だけを覚え、オンにしたら確認なしで送れるようにする
- B. 前の端末で同意していたので、取り込んだらオンにする

4. 返事が届かなかったときの 412
- A. 412 の文を、決めつけない言い方に直すだけにする（「サーバーのバックアップが、この iPhone が最後に送ったものと違います」）
- B. サーバーが控えの中身のハッシュ（受け取ったバイト列の SHA-256）を持つ。条件が合わなくても、送られた中身が今の控えと同じなら、置き換えずに 200 で今の版を返す
- C. 端末ごとの ID を作って一緒に送り、最後に書いた端末を `backups` に持つ。412 でも、最後に書いたのがこの端末なら置き換える
- D. C の端末の ID の代わりに、サーバーのトークン（サインインごとに 1 つ）で、最後に書いたサインインを `backups` に持つ。要約で「最後に書いたのはこのサインインか」を返し、そうなら iOS が今の版で送り直す

## トレードオフ

- 1-A は、操作がいちばん少ない。代わりに、同じ Apple ID で記録を新しく始めたい人にも前の記録が入り、消すには 1 件ずつ消すしかない
- 1-B は、バックアップの欄にまとまり、オン・オフの行（ADR 0060）と同じ形で作れる。代わりに、新しい端末で戻したい人が、自分で行を探すことになる。新しく始めたい人は、記録を付けてからオンにしたときの 412 の確認（「サーバーの N 件を、この端末の M 件で置き換えます」）で初めて前の控えのことを知り、意味が分かりにくい
- 1-C は、戻したい人はサインインの流れのまま戻せ、新しく始めたい人も最初に選べる。代わりに、サインインの直後に聞く画面が 1 つ増え、サインインの結果を受けてバックアップの控えを読む流れを足す
- 2-A は、取り込んだ結果が元の端末と必ず同じになる。1 件のために全部を取り込めないことがある。2-B は、多くを戻せるが、何が欠けたかを伝える画面が要り、曲だけ・記録だけが欠けて数が合わなくなる。値は端末のモデルの `init` で確かめてから送っているので、おかしい値は壊れたか作り替えられた控えでしか起きない
- 3-A は、同意を取ったサインインでだけ送る形（ADR 0058・0059：サインインしたら状態を消し、オフから始める）を崩さない。取り込んだ人は、もう一度オンにする手間がある。3-B は手間がないが、新しい端末で同意の画面を見ないまま送り始める。同意の版を上げた後に、古い同意で送ることにもなる
- 4-A は、作りがほぼ要らない。代わりに、穴そのものは残る。返事を受け取れないたびに自動のバックアップが止まり、本人が設定を開いて「置き換える」を押すまで再開しない
- 4-B は、サーバーだけの変更で、iOS の送るもの・同意の文は変わらない。HTTP の「同じリクエストを何度送っても結果が同じ」という考え方に合い、正しさはサーバーで守る（ADR 0058 の 4-B と同じ考え）。中身が同じなら、ほかの端末が送ったものでも結果は変わらないので、誤って上書きすることはない。代わりに、返事を受け取れなかった後に記録を足してから送ると、中身が違うので 412 のまま残る（そのときは 4-A の文で確認してもらう）。iOS の JSON の書き方が変わってハッシュがずれても、412 になるだけで、記録は失わない。マイグレーションで列を 1 つ足す
- 4-C は、中身が変わっていても直る。代わりに、端末の ID はプライバシーのラベルの Device ID に当たるおそれがあり、送るものが増えるので同意の版を上げる（ADR 0058 の 4-A で避けた理由と同じ）。同じ端末を古い iPhone のバックアップから戻したときは、サーバーにしかない新しい記録を、確認なしで古い記録で上書きする
- 4-D は、送るものも同意も変えずに、中身が変わっていても直る。代わりに、4-C と同じく、同じ端末を古い iPhone のバックアップから戻すとサーバーのトークンも戻るので（Keychain の `ThisDeviceOnly` は、同じ端末のバックアップからは戻る。Apple の文書からの見立てで、試していない）、サーバーにしかない新しい記録を確認なしで上書きする。サーバー・iOS の両方に変更が要り、412 の後に送り直す流れを足す

## 選んだ理由

- 1 は C。自動で取り込むと、同じアカウントで新しく記録を始めたい人が、前の記録を消さないと始められない。取り込むのは空の端末に最初だけ、という一般的な復元の形（iPhone の iCloud バックアップ・トークの履歴など）に合わせ、サインインした直後に 1 回だけ聞く。アカウントは設定の任意の機能なので、取り込まなかった人も、空の間は設定から戻れるようにする
- 2 は A。取り込んだ結果が元の端末と必ず同じになるようにする。おかしい値は壊れた控えでしか起きないので、一部だけ戻すより、何も変えずに理由を出す
- 3 は A。同意はサインインごとに取る（ADR 0058・0059）。取り込みは読むだけなので同意は要らないが、送り始めるのは本人がオンにしてから
- 4 は A＋B。端末 1 台で使っているだけで自動のバックアップが止まるのは、自動にした意味（ADR 0053 の 5-B）をなくす。B はサーバーだけで直せ、送るものも同意も変えず、正しさをサーバーで守る形（ADR 0058 の 4-B）のままでいられる。B で直らない場合（返事を受け取れなかった後に記録を足した）は、A の文で本人に確かめてもらう。C・D は中身が変わっても直るが、古い iPhone のバックアップから戻したときに、サーバーにしかない記録を確認なしで上書きするので選ばない

## 決めたこと

- 取り込めるのは、曲も記録も 0 件の端末だけ。Data 層で、書く直前にもう一度確かめる。曲だけがあって記録が 0 件の端末は空として扱わない
- サインインした直後に、端末が空で控えがあれば、件数と日時を見せて「取り込む」か「取り込まずに新しく始める」かを聞く。控えがなければ何も聞かない。初めて開いたときにサインインを勧める画面は作らない（サインインは今のまま設定から）
- 「新しく始める」を選んでも、サーバーの控えは消さない。端末が空の間は、設定のバックアップの欄に「バックアップから取り込む」の行を残す。記録を付けてからオンにしたときは、今までどおり 412 の確認で前の控えを置き換えるかを聞く
- `restoreAll()` は、`GET /v1/backup` → `schemaVersion` が 1 か → 値を全部確かめる（曲名が空でない・点数が 0〜100・気分と記録の入口が知っている値・id と曲名が重ならない・記録の曲がバックアップにある）→ SwiftData に入れて 1 回だけ保存する。1 件でもだめなら何も書かない。保存に失敗したら戻す。UUID は元のまま、`singCount` は記録の件数から数える
- 取り込めたら、その控えの版を `lastRevision` に置く。バックアップはオフのまま。オンにするときは同意の画面を通る
- 取り込みも、送信・削除と同じ順番待ちで動かし、途中でサインアウトされたら版を書かない
- `backups` に `payload_sha256`（`schemaVersion`・件数・受け取った `payload` のバイト列の SHA-256。jsonb は書き方を変えて保存するので、保存する前のバイト列で計算する）を足す。今ある行は空のままにし、空の行とは一致しないとする
- `PUT /v1/backup` は、条件が合わない・控えがもうあるときでも、送られた中身のハッシュが今の控えと同じなら、置き換えずに 200 で今の版と日時を返す。違えば今までどおり 412
- 412 の文は「サーバーのバックアップが、この iPhone が最後に送ったものと違います」にする

## 見直す条件

- 中身を変えた後の 412 が、端末 1 台でも実際に何度も出ると分かったとき（4 に C か D を足すかを考える）
- テスターから、取り込んだ後にもう一度オンにするのが分かりにくいと言われたとき（3）
- テスターから、サインインの場所が分かりにくい・新しい端末で取り込みに気づかなかったと言われたとき（初めて開いたときの画面を考える）
- 記録のある端末にも取り込みたいと言われたとき（2 台の同期 C2 で考える）
- `schemaVersion` を 2 にするとき（古い形を読む仕組みを足す）
