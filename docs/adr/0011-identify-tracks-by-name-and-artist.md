# 0011. 手入力の曲は曲名＋歌手名で区別し、新しい曲では歌手名を必須にする

- 2026-10-14 提案 ／ 2026-11-19 承認
- 背景：手入力の曲は曲名（`userEnteredName`）だけで同じ曲かを判定しているため、別のアーティストの同名曲（「Lemon」「糸」など）が 1 曲として集計される（#97・#105）。歌手名を足すと、歌手名を足す前に作った曲（歌手名なし）と、同じ曲名で歌手名付きの記録をどうつなぐかも決める必要がある

## 比較した案

1. 歌手名の入れ方
- A. 今のまま曲名だけで区別する
- B. 歌手名を足し、入力は任意にする
- C. 歌手名を足し、新しく曲を作るときは必須にする（既存の曲を候補から選んだときは自動で入る）

2. 歌手名のない前からの曲と、同じ曲名で歌手名付きの記録
- A. 聞かずに、前からの曲に歌手名を補って同じ曲にする
- B. 補わず、いつも別の曲にする
- C. 記録シートで、その曲と同じ曲かを本人に選んでもらう

## トレードオフ

1. 歌手名の入れ方
- A は入力が楽だが、同名曲が混ざる
- B は入力の手間は少ないが、「a / A さん」「a / B さん」「a / 歌手名なし」の 3 つができ、歌手名なしの「a」がどちらの曲か判断できない
- C は初めて歌う曲で入力が 1 つ増える。既存のデータは歌手名がないので、データの型は任意（`String?`）のままにし、必須チェックは記録シートで行う必要がある

2. 歌手名のない前からの曲
- A は操作が増えないが、前からの曲が別の歌手の曲だったときに記録が混ざり、元に戻せない
- B は混ざらないが、同じ曲の記録が「歌手名なし」と「歌手名付き」の 2 曲に分かれる
- C は聞く分だけ操作が 1 回増える。ただ、聞くのは歌手名のない曲を初めて歌手名付きで記録するときの 1 回だけで、答えた後はその曲に歌手名が入るので二度と聞かない。歌うたびに歌手名が埋まっていくので、歌手名を直す画面がなくても前からの曲が整っていく

## 決めたこと

1. C。新しい曲を作るときは歌手名を必須にする。曲名が同じで歌手名のない曲があり、歌手名を空のまま保存したときは、新しい曲を作らずにその曲につなぐ（歌手名を思い出せない前からの曲も記録できるようにする）。記録の編集では曲を変えられないので聞かない
2. C。曲名が同じで歌手名のない曲（歌唱回数 1 回以上）があり、曲名と歌手名の両方が同じ曲がないときは、「前の『曲名』（N 回・歌手名なし）と同じ曲ですか？［同じ曲］［別の曲］」と聞き、答えるまで保存しない
- 同じ曲なら、その曲に歌手名を書き足す（`fillArtistName`）。別の曲なら、前の曲はそのままにして新しい曲を作る
- 候補から歌手名のない曲を押したとき、選曲・曲詳細・提案から歌手名のない曲で開いて曲名を変えなかったときは、本人がその曲を選んだので「同じ曲」を選んだ状態で出す。押し間違えても直せるよう、選んだ後もボタンは残す
- 同じ曲かの判定（`getOrCreate`）は、曲名と歌手名の両方の完全一致だけにする（歌手名が空どうしも一致）。歌手名を補うのは本人が選んだときだけで、`getOrCreate` は補わない
3. Spotify 由来の曲は Spotify の曲 ID で区別するので、歌手名は持たない（[0002](0002-no-persisting-spotify-metadata.md)）

## 選んだ理由

- 1 は C。B では同名曲が混ざる問題が「歌手名なし」の形で残る。歌手名が必要なのは初めて歌う曲だけで、2 回目以降は候補を選べば自動で入る。歌手名はカラオケの採点画面に出ているので、今後、写真から曲名と歌手名を読み取れるようにすれば入力の手間も減らせる
- 2 は C。補う（A）と補わない（B）のどちらも、どこかで記録が混ざるか分かれるかを受け入れることになる。どちらかに妥協するのではなく、ロジックと UI で解決したかった。同じ曲かどうかを知っているのは本人だけなので、アプリが推測で決めずに本人に選んでもらう

## 見直す条件

- 歌手名の入力が記録の手間として重いと分かったとき（写真の読み取りで自動入力できない場合など）
- 「同じ曲ですか？」を聞く回数が多くて邪魔だと分かったとき（歌手名を直す画面を作り、まとめて埋められるようにするなど）
- 表記ゆれ（「米津玄師」「Kenshi Yonezu」）の扱いを決めるとき（#94〜#96）
