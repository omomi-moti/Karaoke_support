# 曲名の一致・検索の方針

**対象:** 記録シートの曲名サジェスト（もしかして）、今後の表記ゆれ対応（#94〜#96）、MusicKit 連携。

**参照実装:** `TrackSuggestionRanker` / `TrackMatchTier`（`Sources/Domain/Helpers/`）、`RecordingSheetViewModel.updateTrackSuggestions(for:)`・`updateArtistSuggestions(for:)`。

---

## 一致の種類と使い分け

| 方法 | 内容 | 向いている場面 | このアプリでの使い道 |
|------|------|----------------|----------------------|
| **完全一致** | 文字列がまったく同じ | 同じものかどうかの判定 | `TrackRepository.getOrCreate` で、曲名と歌手名の両方が同じかで同じ曲か決める（#94 以降は正規化した値での完全一致） |
| **前方一致** | 先頭から一致する | 入力途中の補完 | サジェストの 1 段目 |
| **単語の先頭一致** | 途中の単語の頭で一致する（「live」→「Lemon (Live)」） | 複数の単語でできた名前の補完 | サジェストの 2 段目 |
| **部分一致** | どこかに含まれる | 「探す」画面での検索 | サジェストの 3 段目・検索タブ（`searchLocal`） |
| **読み・かなの統一** | ひらがな/カタカナ、漢字の読みをそろえてから比べる | 日本語の表記ゆれ | 未実装（#95）。比べる前の下ごしらえ |
| **あいまい一致（編集距離など）** | 1〜2 文字違っても当てる | 打ち間違い | 未実装（#96）。他で 1 件も当たらないときの保険 |
| **全文検索インデックス** | 大量の文章を高速に検索する | 数万件以上のデータ | 使わない。端末内の曲は多くても数百件で、SwiftData にもこの機能はない |

## 原則: 判定と並べ方を混ぜない

- **同じ曲かどうかの判定**（`getOrCreate`）は **曲名と歌手名の両方の完全一致のみ**（歌手名が空どうしも一致）。間違えると別の曲の記録や歌唱回数がまとめられ、元に戻すのが難しいため。歌手名のない前からの曲に歌手名を補うのは、本人が「同じ曲」を選んだときだけ（下記「歌手名のない前からの曲」、ADR 0011）。
- **候補の並べ方**（サジェスト）は、前方一致などを使ってユーザーが選びやすい順にする。最終的に曲を決めるのはユーザーのタップ。
- あいまい一致・読みでの一致は **候補を出すためだけ** に使い、同じ曲の判定には使わない。

## 記録シートのサジェスト（もしかして）

### 流れ

曲名の欄と歌手名の欄の両方から引ける（双方向）。候補は最後に打った欄の下に出す。

1. `.task(id: manualName)` から `updateTrackSuggestions(for:)`、`.task(id: manualArtistName)` から `updateArtistSuggestions(for:)` を呼ぶ（入力が止まってから 300ms 後に検索）
2. **絞り込み**: 曲名の欄は `searchLocal`（`userEnteredName` の部分一致）、歌手名の欄は `searchLocalByArtist`（`userEnteredArtistName` の部分一致）。どちらも DB 側の `localizedStandardContains`
3. 曲名と歌手名の両方が、ある曲と完全に一致したら何も出さずに終わる（下記「その他の決めごと」）
4. 歌唱回数 0 の曲と、Spotify ID を持つ曲を除く。曲名の欄では、曲名が完全に同じで歌手名のない曲も除く（候補ではなく「同じ曲ですか？」で聞くため）
5. **並べ替え**: `TrackSuggestionRanker.rank`。歌手名の欄では、段の判定と 4 番目の比べる文字を歌手名にする（`matchedText: \.userEnteredArtistName`）
6. 曲名の欄では、歌手名の欄に何か入っていれば、その歌手名を含む曲を先に並べ、ほかの歌手の曲はその下に残す（歌手名を先に入れたときに選びやすく、打ち間違いやカバーでも選べるように）。先頭 5 件を表示する。曲名の欄では「曲名　歌手名」、歌手名の欄では「歌手名　曲名」の順に出す。歌手名のない曲は「歌手名なし」と出す
7. 歌手名の欄では、曲の候補の上に、候補の曲の歌手名を重ねずに最大 3 件、歌手名だけで出す（打った歌手名と同じものは出さない）。押すと歌手名の欄だけに入り、曲名の欄は変えない。初めて歌う曲でも歌手名を候補から入れられるようにするため。押した歌手名のままの間は候補を出し直さず、曲名の欄が空ならカーソルを曲名の欄に移す
7. 候補を押すと、曲名と歌手名の両方が入力欄に入る

**5 件に絞る前に並べ替える。** `searchLocal` は歌唱回数の多い順に返すため、先に絞ると、前方一致の曲が 6 件目以降にあった場合に切り捨てられる。

### 並べ方

2 曲を比べるとき、上から順に見て、違いが見つかった時点で決める。

| 順 | 条件 | 並び | 理由 |
|----|------|------|------|
| 1 | 一致の段 | 前方一致 > 単語の先頭一致 > 部分一致 | 今打っている文字に合っているかが最優先。「a」と打った人は a で始まる曲を探していることが多い。段の中では、曲名の先頭で始まる前方一致、途中の単語が打った文字で始まる単語の先頭一致（「live」→「Lemon (Live)」）、単語の頭ですらなく含んでいるだけの部分一致、の順に意図に近い |
| 2 | 歌唱回数 | 多い順 | 同じ段なら、よく歌う曲ほどまた歌う可能性が高い |
| 3 | `updatedAt` | 新しい順 | 回数も同じなら、最近触った曲を上にする（下記の注意を参照） |
| 4 | 曲名 | 辞書順 | 毎回同じ並びにするための保険。`sorted` は条件が同じ要素の並びを保証しない |

### 段の判定（`TrackSuggestionRanker.tier(of:for:)`）

良い段から順に確認し、当てはまった時点で決める。

1. `range(of:options:)` に `.anchored` を付けて **先頭から一致するか** → 前方一致
2. 一致した位置の **直前の文字が空白・記号** か → 単語の先頭一致。1 回目の一致が単語の途中でも、後ろの一致を続けて確認する（「an」→「Banana Anthem」は Anthem で単語の先頭一致）
3. どちらでもない → 部分一致

**比べ方のルール:** DB 側の `localizedStandardContains` で一致した曲を段の判定で取りこぼさないよう、それより広めの条件（`.caseInsensitive` / `.diacriticInsensitive` / `.widthInsensitive`）にしている。ここが DB 側より狭いと、DB で見つかった曲が並べ替えで不当に下の段に入る。

| 違い | DB 側（`localizedStandardContains`） | 段の判定 |
|------|------|------|
| 大文字小文字（「LEMON」と「lemon」） | 区別しない | 区別しない |
| 全角半角（「ｌｅｍｏｎ」と「lemon」、「ﾏﾘｰ」と「マリー」） | **区別する** | 区別しない |
| 日本語の濁点・半濁点（「ガ」と「カ」） | 区別する | 区別する（`.diacriticInsensitive` でも区別される） |
| ひらがなとカタカナ（「まりー」と「マリー」） | 区別する | 区別する |

全角半角だけが違う曲は、DB の絞り込みで落ちるので段の判定には届かない。並べ方ではなく、DB の検索そのものを正規化した値で行う必要がある（#94）。上の表は Foundation 単体で確認した結果で、SwiftData が SQL に変換して検索したときも同じかは未確認。

**単語の区切り:** 「直前が空白・記号」で判定する。`enumerateSubstrings(.byWords)` は日本語を形態素で区切り（「打上花火」→「打上」「花火」）、区切り位置が予想しづらいため使わない。空白のない日本語の曲名は、ほぼ「前方一致」か「部分一致」になる。

アポストロフィ（`'` と `’`）は、Unicode の分類では記号（句読点）だが、単語の途中にも頭にも使われる。文字にはさまれている場合と先頭・空白の後ろの場合は、Unicode の単語の区切り規則と同じ扱いにしている。数字にはさまれている場合（90's）だけは独自の判断で、Unicode の規則では「90」と「s」の 2 語に分かれるが、曲名としては 1 語とみなす方が自然なため単語の途中として扱う。

| アポストロフィの位置 | 例 | 後ろの文字の扱い |
|------|------|------|
| 文字・数字にはさまれている | Don't、Rock'n'Roll、90's | 単語の途中 |
| 先頭、または空白の後ろ | 'Round Midnight、Take ’Em All | 単語の先頭 |

文字の並びだけでは英語の短縮形（Don't）とフランス語などの省略形（L'amour、O'Brien）を見分けられないため、後者も単語の途中として扱う（「amour」で「L'amour」は部分一致）。カラオケの曲名では短縮形の方がずっと多く、間違えても段が 1 つ下がるだけで候補からは消えないため、仕様として受け入れる。判定を決めたケースは `TrackSuggestionRankerTests` の「段の判定」の表にまとめてあり、ルールを変えたときにどのケースが変わったかがわかる。

### その他の決めごと

- **1 文字目から出す。**（両方の欄で同じ） 1 文字でも段分けで前方一致が上に来るので、部分一致を除外しない。
- **曲名と歌手名の両方が既存の曲と完全一致なら何も出さない。** そのまま保存すれば `getOrCreate` で既存の曲につながるため。判定は `getOrCreate` と同じ条件（Spotify ID なし・曲名と歌手名が完全一致）で、候補から除く歌唱回数 0 の曲も含める。曲名だけが一致して歌手名の欄が空のときは、同じ曲名で歌手名付きの曲を候補に出す（押せば歌手名まで入る）。
- **歌唱回数 0 の曲は候補に出さない。** 記録を全部消した曲（打ち間違いで作った曲など）は Track だけ残るため。
- **Spotify ID を持つ曲は候補に出さない。** 候補を押すと曲名と歌手名が入力欄に入り、保存時の `getOrCreate(spotifyTrackId: nil, …)` は Spotify ID を持たない Track しか探さないため、既存の曲につながらず別の Track が作られてしまう。
- **一致する曲がなければ「候補はありません」を出す。** 検索に失敗したときは出さない（候補があるのに無いと誤解させないため）。曲名の欄で、候補はないが曲名が同じ曲はある（歌手名なしの曲だけ・歌唱回数 0 の曲だけ）ときも出さない。
- 候補を押すと入力欄の文字が置き換わる（曲を固定表示にするモード切り替えはしない）。

### 歌手名のない前からの曲

歌手名を足す前に作った曲は歌手名が空。同じ曲名を歌手名付きで記録するとき、その曲につなぐかはアプリが決めず、本人に選んでもらう（ADR 0011）。

| 場面 | 動き |
|------|------|
| 曲名が同じで歌手名のない曲（歌唱回数 1 回以上）があり、曲名と歌手名の両方が同じ曲はない | 歌手名の欄の下に「前の『曲名』（N 回・歌手名なし）と同じ曲ですか？［同じ曲］［別の曲］」を出す。答えるまで保存せず、カードに「『同じ曲』か『別の曲』を選んでください」と出す |
| 候補から歌手名のない曲を押した | 歌手名の欄にカーソルを移し、「同じ曲」を選んだ状態で出す |
| 選曲・曲詳細・提案から歌手名のない曲で開き、曲名を変えていない | 「同じ曲」を選んだ状態で出す |
| 「同じ曲」で保存 | その曲に歌手名を書き足す（`fillArtistName`。`updatedAt` は変えない）。以後は曲名と歌手名の完全一致でつながるので聞かない |
| 「別の曲」で保存 | 前の曲はそのままにして、新しい曲を作る |
| 歌手名を空のまま保存 | 曲名が同じで歌手名のない曲があればその曲に保存し、なければ「歌手名を入力してください」で止める |

答えは曲の id と一緒に持つ。曲名を変えて別の曲が見つかったら、前の答えは使わない。保存の直前にもう一度 `searchLocal` で曲名が同じ曲を探してから決める（待ち時間の間に保存したときも聞きもらさないため）。

### 既知の制約

- **`updatedAt` は「最後に歌った日時」の近似。** 記録の保存だけでなく、編集・削除でも更新される。また歌唱日時を過去にして保存しても、保存した時刻になる。正確に出すには曲ごとに記録（`sessions`）を読み込む必要があり、回数も同じときの決め手にすぎないためコストが見合わないと判断した。
- **候補を選ばずに打ち切ると、別の曲として保存される。** 「lemon」と「Lemon」、「米津玄師」と「Kenshi Yonezu」は `getOrCreate` の完全一致では別の曲になる。#94〜#96（正規化）で対応する。
- **バックアップにはまだ歌手名が入らない**（Debug・Beta）。`BackupSnapshotTrack` は曲名だけを持ち、取り込みは曲名の重なりを不正として断るため、曲名が同じで歌手が違う 2 曲を持つ端末のバックアップは取り込めない。次のブランチで、バックアップの形・`schemaVersion`・サーバーを合わせて直す。
- **全角半角だけが違う曲は候補に出ない。** DB の絞り込み（`searchLocal`）が全角半角を区別するため。#94 で対応する。
- **ひらがなとカタカナ、漢字と読みの違いは候補に出ない。** 「まりーごーるど」で「マリーゴールド」、「うちあげ」で「打上花火」は出ない。#95 で対応する。
