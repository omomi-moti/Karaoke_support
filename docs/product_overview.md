# プロダクト概要

## Problem

ひとりカラオケでは、次に何を歌うかを毎回その場で決める。迷っている間も時間は過ぎ、**歌える時間が減る**。前に歌って良かった曲や、そのとき歌った気分は、その場ではなかなか思い出せない。

からログは、歌った曲に**選んだ理由（気分）・また歌いたいか・歌い切れたか**を残し、今の気分に合う曲につなげる。記録はそれ自体が価値ではなく、**選曲を軽くするための手段**。

### 誰のためか

ひとりカラオケをする人。周りに合わせる必要がなく、そのときの気分や選ぶ軸がそのまま選曲に出るので、自分の記録から次の曲を出しやすい。

複数人カラオケは、今は対象外にしている。3 人（大学の学生エンジニアの友人、知り合いの iOS エンジニア、エンジニアではない友人）にアプリを触ってもらったところ、複数人で歌うときは、歌いやすさ・盛り上がり・同行者・人数など、選ぶ基準が増えることが分かった。

### ほかのアプリとの違い

- 音楽のサブスクは聴くためのもので、歌うことに最適化されていない
- カラオケ機種の公式アプリは、歌った履歴と点数を出すだけで、なぜその曲を選んだかが残らない
- カラオケ店の選曲端末は大勢向けで、個人に寄っていない

からログはサブスクを主役にした選曲をしない（これから入れる Apple Music の曲の候補も、曲名の入力を助けるものにとどめる）。候補の上には、言葉にしにくく自分の記録にしか残らないもの（また歌いたいか、そのとき歌った気分）を出す。

| 課題 | アプローチ |
|------|------------------|
| 次に何を歌うか迷い、歌える時間が減る | **選曲画面**で気分を選ぶと、最新の記録がその気分の曲が並ぶ。履歴タブで保存したときは、**保存直後の提案**で同じ気分の曲を最大 2 曲出す。候補は自分の記録（最新の気分・最高点・久しぶり度・ハート）から端末の中で計算する |
| 前に歌って良かった曲を思い出せない | 歌った直後に**ハート**（また歌いたい）を付けると、選曲画面の「また歌いたい」に気分が違っても出て、同じ気分の候補では必ず上に来る。ハートは歌うたびに付け直す |
| 練習の続きの曲が見つからない | **Practice** を選ぶと、「練習中の曲」と「歌い切れなかった曲」が分かれて並ぶ。最新の記録で歌い切れなかった曲は、ほかの気分の候補には出さない |

## ユーザー価値

- **曲選びの迷いが減る** — 選曲画面で今の気分を選ぶと、前にその気分で歌った曲が並ぶ。履歴タブで保存したときは、保存した直後に次の 1 曲の候補が出る
- **また歌いたい曲が上に出る** — ハートを付けた曲は、気分が違っても選曲画面の「また歌いたい」に出て、同じ気分の候補では必ず上に来る
- **Practice で練習の続きを選べる** — 「練習中の曲」と「歌い切れなかった曲」（そのとき書いたメモ付き）が分かれて並ぶ。今日歌った曲も消えずに下へ回るので、同じ日に何度でも歌い直せる
- **歌った曲をすぐ残せる** — Intent + スコア + 歌い切れたか + メモ + ハートで、次の選曲に使う材料を残す。曲は曲名と歌手名で区別し、曲名からも歌手名からも「もしかして」で前に歌った曲を選べる。前に歌った曲は、検索タブで曲名か歌手名から探すか、最近歌った曲から選んで、すぐ記録を始められる
- **履歴と曲詳細で見返せる** — 履歴を Intent で絞り込み、曲詳細で点数の推移を見られる。曲詳細から記録を直したり、曲の歌手名を直したり（打ち間違いで分かれた曲はまとめられる）、＋で同じ曲をもう一度記録したりできる
- **データの扱いが分かる** — 設定タブに、記録をどこに保存するかと、サポートのページ・プライバシーポリシーへのリンクがある（ADR 0068）
- **（開発中・Debug と Beta のビルドだけ）記録をバックアップできる** — 設定タブの「バックアップ」から同意してオンにすると（サインインしていなければ、同意の画面で Sign in with Apple でサインインしてそのままオンにできる）、アプリを閉じたときにメモを除いた記録を自動でサーバーに送る。ログアウトとアカウントの削除もできる。機種を変えたときは、曲も記録もない端末でサインインすると、バックアップを取り込むかを聞く（記録がない間は、設定からも、履歴・選曲の空の画面からも取り込める。空の画面ではその場でサインインできる）。取り込めたときにバックアップがオフなら、オンにするかを聞く

## Intent（歌唱の意図）— プロダクト設計の核

一人カラオケで「歌う理由」は毎回異なる。ストレス発散で叫びたい日もあれば、しんみりバラードに浸りたい日もある。しかし既存のカラオケアプリは「曲名 + 点数」しか残さないため、**なぜその曲を選んだかという文脈が消える**。

からログでは、この「歌唱の意図」を **Intent** という 3 つのモードで表現する:

| Intent | 意味 | ユーザーの感情 | 選曲傾向 |
|--------|------|---------------|----------|
| 🔥 **Shout** | 叫ぶ・発散する | ストレス発散、テンションを上げたい | アップテンポ、ロック、アニソン |
| 🌙 **Emo** | 感情に浸る | しんみりしたい、感動したい | バラード、しっとり系、思い出の曲 |
| 🎤 **Practice** | 練習する | 上手くなりたい、高得点を狙いたい | 苦手な曲、新曲、音域チャレンジ |

### なぜ 3 つに絞ったか

V1 時点では、一人カラオケの動機はおおむね「発散」「感情」「上達」の 3 軸に**集約できるのではないか**と推測し、この前提で Intent を 3 つに絞って実装している（本番運用後のユーザー検証は別途）。選択肢が多すぎると記録時の認知負荷が上がり、少なすぎると文脈が残らない、という一般論に合わせ、**3 択なら 1 秒で選べて、かつ振り返り時に意味のある軸になる**バランスを狙った。

### プロダクト価値との接続

Intent は単なるラベルではなく、**選曲の基盤**として設計している:

- **選曲トリガー**: 履歴タブで保存した直後に、その記録と同じ気分で前に歌った曲を出す。「今日は Shout の気分」なら、選曲画面で Shout を選ぶと、最新の記録が Shout の曲が並ぶ。最新の記録で歌い切れなかった曲は、候補に出さない
- **練習の続き**: 選曲画面で Practice を選ぶと、「練習中の曲」（Practice で歌い切れた曲。点数アップ）と「歌い切れなかった曲」（気分に関係なく、そのとき書いたメモ付き）が分かれて並ぶ。ハートを付けた曲が上に来て、今日歌った曲も消えずに下へ回るので、同じ日に何度でも練習の続きを選べる。Practice 以外の気分で歌い切ると、挑戦中から外れる
- **傾向の振り返り**: 履歴を Intent で絞り込み、「最近 Practice ばかりだな」といった自己発見を促す

### 技術実装

```swift
/// 歌唱の意図（ドメインでは enum、永続化時は RawValue で扱う）
enum Intent: String, Codable, CaseIterable, Sendable {
    case shout
    case emo
    case practice
}
```

`Intent` は `String` RawValue の enum として定義し、SwiftData の永続化時は自動的に RawValue（文字列）で保存される。`CaseIterable` でフィルター UI の選択肢を自動生成し、`Sendable` で Swift Concurrency の安全性を保証している。Intent での絞り込み（履歴）は `SwiftDataSessionRepository` が SwiftData からセッション一覧を取得し、メモリ上で絞り込む設計（DB 側の Predicate による enum 絞り込みは、当時の最低対応 OS だった iOS 17.0〜17.2 で落ちたため避けた。今は iOS 26 が最低対応 OS で、Predicate に戻すかは見直し候補 — 詳細は [ADR 0007](adr/0007-filter-intent-in-memory.md) 参照）。
